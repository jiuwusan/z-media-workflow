# 开发规范

## 环境与验证

使用 Node.js >=22.13、npm，根 package-lock.json 和 web/package-lock.json 分别管理后端与界面。不运行 scripts/check-connections.mjs 作为离线检查，它会连接配置的真实服务。

`npm ci --ignore-scripts` 安装后端开发依赖；`npm ci --prefix web --ignore-scripts` 安装前端；`npm start` 启动，`npm run dev` 开发，`npm run dev:web` 启动界面开发服务。

- `npm run lint`：Acorn 语法 lint，覆盖 src/scripts/test/web 的 JS/MJS，不改写代码；这是语法检查，不宣称具备 ESLint 语义规则。Vue 模板由构建编译验证，项目当前无 TypeScript 类型检查任务。
- `npm run check:architecture`：AST 依赖方向、循环、动态加载与直接 I/O 约束。
- `npm test`：离线 Node 测试，覆盖 API/认证/CSRF、配置、SQLite、持久化、恢复、工作流和注入上游。
- `npm run build`：Vite 前端构建。`npm run check` 顺序执行上述全部步骤。
- `npm run test:ui` 与 `npm run test:pm2` 为独立可选交付检查，要求 Playwright 浏览器/PM2 运行环境；涉及 UI 或生命周期变更时运行并记录结果。真实连接检查必须获得明确服务测试授权。

## 运行约定

层边界见 architecture.md，新增纯规则放 domain，文件和 SQLite 放 storage，HTTP 放 gateway，路由不创建服务。服务通过组合根装配，保留 http 注入参数。服务输入输出使用普通值，不传 Koa ctx：认证接收 sessionId/token 和是否校验 CSRF 的布尔条件，恢复接收挑战 token，首次配置接收 input/cookieToken/csrfToken 命令；HTTP 读取、Cookie 设置和 state 写入集中在 controller/middleware。错误用 AppError，HTTP 边界统一转换；保持方法、URL、状态码、响应字段、CSRF、会话、Webhook 权限、超时与重试语义。删除文件、清理、重命名及自动识别都需先校验和记录意图，失败不能悄悄继续破坏性步骤。

Vue 中保持表单 label、键盘操作、加载/禁用状态，异步请求有取消或过期响应保护；输出文本使用 Vue 默认转义，禁止拼接未清洗 HTML。数据库事务只负责本地一致性，不在事务中等待不受控网络；单实例读写与现有崩溃恢复规则保持一致。

CI test 任务安装两套 npm 锁并运行 check，镜像发布依赖检查成功；PR 只构建不推送。部署前停写并备份整个 data（SQLite 及其配套文件、配置/恢复相关文件），记录旧镜像；按既有 README/Compose 检查端口、数据卷、权限、回调地址和健康。恢复时使用兼容备份，不删卷，不混用两个写实例。

## 编码、变更与审查

使用 UTF-8、文件末尾换行，保持相邻文件缩进和现有工具链；不批量格式化无关文件。模块按职责命名，优先小函数、明确输入输出及可替换的外部依赖。禁止循环依赖、隐式全局状态、静默吞错和为目录形式添加无行为转发；遗留兼容导出仅供已有调用方，新运行代码使用所属层。

修改行为前先复现并覆盖失败路径；纯逻辑测试输入、输出与边界，用例测试状态、并发、取消和失败隔离，适配器测试协议和文件边界，交付前执行完整检查。外部系统用虚构数据、临时目录及注入依赖，不连接私人服务或发送真实通知。异步资源在关闭时清理，晚到响应不得覆盖新状态，失败不能标记为成功。检查器是静态约束，不是安全沙箱，反射、别名、第三方副作用与状态所有权仍需人工审查。

新增依赖说明用途、许可证及运行成本，区分生产与开发依赖，同时更新原有锁文件，不手改解析结果。变更接口、数据格式、环境参数或部署流程时同步 README 和设计文档；说明兼容、失败场景、回滚方法。审查先看安全、数据所有权与并发，再看可读性。

## 安全、日志与配置

不得提交、读取输出或在测试快照中暴露 .env、凭据、真实私人服务地址、生产数据。日志仅输出脱敏摘要，异常不透传密钥、上游正文或堆栈给终端用户。外部请求应定义超时、取消、响应校验与错误转换；新增写操作需要授权、输入校验和重复提交防护，客户端校验不能替代可信边界的校验。配置由现有配置入口管理，不在组件或业务函数里散落环境变量。

## Git 与交付

默认当前分支工作，不擅自创建分支/worktree、提交、推送或发布。获授权提交时用 `<类型>: <中文摘要>`；项目迁入 E:\code 后必须使用 `<类型>: <B/C/D><准确飞书工作项ID>-<中文摘要>`，默认 C，不得省略或编造 ID。

交付检查：需求和失败路径实现完整；完整检查真实执行；无越层、循环、敏感信息、无关变更或遗留调试输出；锁文件一致；说明命令、结果、跳过项和真实环境限制。未经执行的桌面、浏览器、Docker 或真实服务检查不能声称通过。部署前记录当前版本、配置与数据备份，升级后验证健康及只读关键路径；回滚恢复旧产物、匹配配置和兼容数据，禁止新旧实例同时写共享数据。
