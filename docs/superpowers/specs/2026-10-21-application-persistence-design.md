# 应用配置与业务状态持久化设计

日期：2026-10-21

## 已确认需求

在现有 workflow.sqlite 上继续迁移媒体识别游标、待识别 ID、种子清理记录、配置修改记录、登录失败次数与临时封禁、清理开关等业务设置，以及全部应用配置。用户清单中两次出现的“配置修改记录”合并为一项。

游标不自动读取 media-cursors.json，不提供启动时的旧文件兼容加载。首次运行引导包含可跳过的“游标同步”步骤：管理员可以粘贴文件完整 JSON 并同步，也可以明确选择跳过，使用空游标完成初始化。引导完成前工作流保持暂停。手动同步仅在引导中提供，初始化完成后不提供“游标管理”页面或再次同步接口。

全量配置也不自动导入 config.json。数据库尚无应用配置时，无论新部署还是旧版本升级，都重新进入首次运行引导，由管理员重新设置账号和连接参数。

首次初始化生成 passkey 文件并保存在数据目录。用户已选择：验证 passkey 后显示用户名并允许设置新密码，不返回原密码。登录会话保持内存存储，服务重启仍需重新登录。默认端口保持 3000，Docker 可以使用自定义宿主机端口映射。

## 总体结构与交付顺序

继续使用现有 SQLite 数据库、WAL、FULL 同步和单消费者模型，不引入额外数据库服务。升级 schema，保留现有任务、候选和动作记录。数据库连接上移到应用启动入口，在读取应用配置之前打开；配置、认证、游标和清理记录 Repository 共用连接，各自负责数据访问。

按三个依赖阶段交付，各阶段独立验证：

1. 配置与认证基础：数据库启动、完整配置、业务设置、配置审计、账号哈希、passkey 找回、持久登录限制。
2. 游标迁移与手动同步：数据库游标、粘贴导入界面、与工作流完成状态的本地事务。
3. 种子清理执行历史：持久执行记录、重启核对、分页查询界面。

选择共用数据库可以让设置与审计、游标与任务收尾分别在本地事务中提交。另建独立数据库会失去这些事务关系，继续保留多个可写 JSON 文件则不能达到本次全量迁移目标。

## 全量配置与业务设置

应用固定从 data/workflow.sqlite 读取持久配置；数据库位置不能再依赖 config.json 中的字段。HOST、PORT、PUBLIC_URL、外部服务连接、密钥、超时、队列容量、分类列表、清理设置等全部纳入数据库。runtime.json 只保存当前实际监听地址，继续供进程外健康检查读取，不作为配置源。

新的配置记录包含递增 revision。配置保存采用事务内比较 revision、校验、新值写入、审计记录写入，冲突返回 409。基础配置继续保存后重启生效；剧集分类与清理设置继续即时生效。它们使用同一配置 Repository，不能绕过审计或覆盖其他尚未生效的配置。

不读取、导入或写回 config.json，也不提供旧配置文件的运行时兼容。升级现有部署时保留原文件供管理员自行参考，但引导页面不从中预填任何设置。管理员通过首次运行引导重新填写账号、服务连接和访问地址；未填写的可选设置使用程序默认值，业务分类和清理开关需重新设置。

数据库没有应用配置时显示首次运行引导，默认监听 0.0.0.0:3000。步骤依次为账号设置、服务连接与访问地址、游标同步（可跳过）、完成初始化。配置、账号哈希、恢复凭据及导入的游标或明确跳过的空游标必须作为一次初始化事务提交，失败不能产生半初始化状态。首次设置完成前不启动已有工作流消费者；旧任务、候选和队列保留在数据库中。新部署与升级部署均在完成引导后恢复工作流，不再要求登录后单独执行首次游标同步。后续修改监听端口仍通过重启生效。

ADMIN_PASSWORD 从配置文档中移出，认证表保存独立随机盐与 scrypt 哈希及参数。表单保留“密码留空不修改”的语义；配置校验和 restartRequired 计算改为使用凭据版本，而不要求加载原始密码。连接密钥存入受目录权限保护的数据库，普通查询只返回已设置标记。此次不引入外部密钥管理或新的数据库加密依赖。

移除已失效的 MEDIA_CURSOR_FILE 可编辑项，仅在首次运行引导中接受既有游标 JSON 格式，不新增日常游标导入/导出功能。配置示例只作为首次运行表单填写参考，不再作为应用读取的配置文件。旧通知脚本中的配置文件只负责脚本自身连接参数，不属于服务端配置源，继续支持。

## passkey 文件与账号恢复

文件固定为 data/passkey，内容为加版本标记的 32 字节随机恢复密钥。它是本应用的恢复密钥文件，不涉及浏览器 WebAuthn。文件使用独占创建方式，POSIX 权限为 0600；Windows 依赖数据目录 ACL。数据库只保存恢复密钥摘要，不将明文密钥写入数据库、日志、URL 或常规配置响应。

首次运行引导提交时，先创建并落盘 passkey 文件，再事务提交配置、账号哈希、passkey 摘要和游标初始化结果；新部署和升级后重新引导均采用这一流程。提交前进程中断可能留下孤立文件；下次尚未初始化时校验其格式并继续使用，不覆盖或自动更换。数据库配置已完成初始化时不得因文件缺失而开放首次运行引导或生成新的有效恢复凭据。

登录页增加“找回账号”入口：输入文件内的恢复密钥 → 服务端校验成功 → 返回用户名及短时、一次性的恢复凭证 → 用户输入并确认新密码 → 更新密码哈希、递增凭据版本、作废全部登录会话和恢复凭证。新密码至少 8 位，完成后立即可用，无需重启。用户名不在未验证的找回接口中公开。

恢复凭证保存哈希、失效时间和已使用状态，有效期 5 分钟；创建/消费通过数据库事务处理，绑定生成时的凭据版本。原始 passkey 不作为恢复凭证返回客户端。passkey 本身保持稳定，正常修改密码不会更新文件内容。

找回流程使用短时同源 nonce 与 CSRF 校验，不复用普通登录会话；错误密钥返回统一错误。独立的找回限流与登录限流均落库。恢复流程不把新密码、原密钥、恢复凭证写入修改记录。登录状态已失效后，旧进程缓存也不能继续接受旧凭据，认证需检查持久凭据版本。

passkey 文件丢失时仍可用现有账号登录；无法取得恢复密钥时不能使用找回功能，不允许通过文件丢失绕过认证。数据库备份与 passkey 文件需要一起保存。旧 config.json 含有之前的明文密码，文档明确提示管理员在确认升级后自行妥善保管或删除，程序不擅自删除。

## 登录失败次数与临时封禁

以命名空间和客户端 IP 作为键，持久保存窗口开始时间、失败次数和封禁截止时间。登录保持现有 15 分钟窗口、最多 10 次尝试的行为；成功登录清除对应登录计数。找回接口采用独立的同等窗口，不与普通登录共用额度。

计数和封禁判断通过事务完成，不能因重启清空，也不能通过并发请求绕过阈值。只清理已过期记录，不通过容量淘汰未过期封禁。客户端 IP 使用现有 TRUST_PROXY 规则；不能直接信任任意客户端传入的转发头。持久限制不依赖完整请求头或密码内容。

## 配置修改记录

记录时间、操作来源（初始化、管理员、恢复流程）、配置 revision、变更字段和脱敏前后值。普通字段可以显示前后值；密码、API Key、回调令牌、passkey、恢复凭证等仅记录“已设置/已更新”等标记，不保存原值或可反推原值的摘要。

覆盖基础配置、剧集分类、清理开关、密码修改、账号恢复和游标同步操作。游标同步只记录影响范围与数量，不保存大份原始 JSON 到审计表。配置与对应审计记录在同一事务中提交，审计失败时配置也不生效。

在“基础配置”提供修改记录分页入口，按递增 ID 倒序排列，显示操作者来源与字段差异。审计默认保留 90 天，最多 10000 条，按终态记录清理，不复用工作流 MAX_JOBS。

## 媒体游标与手动同步

数据库保存服务地址、媒体库 ID、媒体类型、日期水位，以及同日期已确认 ID、pending ID、无日期已确认 ID。保持现有识别语义：pending 必须重试，日期晚于水位或同日期未确认的媒体需要处理；不能仅因存在 ProviderIds 而跳过。

在首次运行引导的“游标同步”步骤提供完整 JSON 输入框、校验与范围数量预览，以及“同步并继续”和“跳过”操作；“同步并继续”只保存引导中的选择，最终完成初始化时统一提交到数据库。无效输入不能作为同步结果继续，也不能被自动视为跳过；用户可以明确点击跳过并放弃已输入内容。跳过时提示：空游标可能使存量媒体重新进入待识别范围，初始化完成后不再提供手动同步入口。

引导支持既有 { version: 1, libraries: ... } 全量内容。服务端严格校验版本、范围键、日期和 ID 数组，重复 ID 去重；任何一个范围非法则整次拒绝。页面与初始化接口支持最多 10 MiB 游标 JSON，其他普通接口继续使用原请求体限制。“待识别媒体”页面不增加“游标管理”，不提供已初始化状态下的手动同步能力。

同步完整接收 JSON 中的日期、ids、pending、undated，不是仅追加 pending ID。预览显示范围与 ID 数量，最终完成初始化时将该游标快照与配置、账号及审计一并提交。提交事务内重新检查尚未初始化；并发初始化只有一次能够成功，其余返回 409，不能覆盖已生效的配置或游标。初始化完成后引导的预览及同步请求均拒绝处理，无论之前选择了同步还是跳过。

首次运行引导未完成时暂停工作流消费和新增工作流请求。管理员在引导中完成同步或明确跳过后，游标均视为已初始化；跳过不留下“待首次同步”阻塞标记。不能在管理员完成引导前自动用空游标消费旧队列。初始化审计区分“已同步”与“已跳过”，不保存原始 JSON。

引导内同步或跳过在消费者暂停时提交，可以保留数据库中已有的排队、待确认和中断任务；初始化成功后才分类恢复旧 running 动作并顺序消费 queued 动作。无匹配服务地址的范围按原键保留并明确提示，不隐式映射到当前 Jellyfin，也不验证每个历史媒体 ID 是否仍存在。初始化之后游标只由正常工作流及其恢复逻辑自动维护。

游标确认与对应工作流条目 completed 更新使用同一数据库事务；外部 HTTP 调用保持事务外。启动恢复使用相同的本地收尾事务。若导入的旧备份缺少中断条目的 pending ID，只有在持久写入意图及外部回读均验证通过后，才允许在收尾事务中补登记并确认该条目，不能据此跳过未验证媒体。人工纠错始终不修改识别游标。工作流 SQLite 既有记录不因游标同步而删除或改写。

## 种子清理执行记录

每次合法的预览/清理请求先提交执行记录，再查询和操作 qBittorrent。保存来源（页面或回调）、服务地址、dryRun、deleteFiles、开始/结束时间、匹配与成功/跳过/失败数量及脱敏错误。保存每个目标的 hash、名称、状态、处理结果和时间。清理历史独立于普通工作流队列，不改变已有串行清理锁和页面重启检查。

实际删除前提交逐条删除意图，收到结果后按现有回读规则核实。进程中断后将未结束的清理批次标记 interrupted；只核对对应 qBittorrent 服务中种子是否存在：不存在可记为“种子已不存在”，仍存在或不可查询则保留中断状态。不自动再次执行删除，尤其不能重复发送 deleteFiles=true；不存在的种子也不能证明其下载文件已被删除。

服务地址变化时保留历史，不向新服务核对旧执行。数据库无法保存意图时停止发送删除请求，返回失败；不允许先删后补历史。校验失败、权限失败、重复清理锁拒绝不作为已执行的清理批次。

“种子清理”页面增加历史列表和详情，按批次 ID 倒序分页，区分预览、实际执行、失败和中断。默认保留 30 天、最多 1000 个已结束批次；未解决的中断记录不自动清理。此处仅查询与展示，不新增“重放历史删除”的按钮。

## 数据与生命周期边界

新增配置、凭据、恢复凭证、登录限流、配置审计、游标及游标成员、清理批次及条目表，沿用现有任务表；按 Repository 职责拆分，不让控制器直接读写 SQL。结构迁移必须在事务内执行，失败不删除数据库，也不降级到 JSON 模式。

只有一个应用级数据库连接所有者：引导、配置、认证和工作流共用该生命周期。关闭时停止接收写入，等待当前工作流/清理收尾后关闭；超时由进程退出中断，下一次启动分类恢复。初始化状态读取数据库记录，不能以数据库文件是否存在判断初始化完成。

基础配置更新仍需 PM2 页面重启；账号恢复的密码更新即时生效。端口映射仍只调整 Docker 宿主端口及外部 URL，容器内默认端口为 3000。备份改为停止服务后备份整个 data 目录，至少包含数据库、WAL/SHM、passkey；runtime.json 可重建。

## 验收

- 旧 schema 升级后任务/候选/队列完整保留；数据库无应用配置时重走首次运行引导，即使存在有效或损坏的 config.json 也不读取。初始化失败不能产生半初始化状态。
- 禁止任何启动路径自动读取 media-cursors.json；引导中的完整 JSON 粘贴可以同步日期、ids、pending、undated，非法输入或并发初始化均不能部分覆盖。
- 新部署与升级部署均可在引导中同步或跳过；同步失败不能完成半初始化，明确跳过后空游标可正常启用工作流，登录后不再被首次同步流程阻塞。
- 无论引导时同步还是跳过，初始化完成后均没有“游标管理”入口，也不能重新调用引导接口覆盖游标；重启不再次开放同步步骤。
- 工作流正常完成及崩溃恢复中，游标与条目结果事务一致；纠错不写游标。
- 所有配置入口共用 revision 和审计，切换清理设置不会覆盖待重启的基础配置。
- 初始化/升级生成 passkey；文件创建失败不能完成初始化；孤立文件可恢复，文件丢失不开放初始化。
- 找回只在验证密钥后显示用户名；恢复凭证超时、重复消费、凭据版本变化都失效；并发重置只能成功一次。
- 密码以哈希保存；配置 API、日志、审计和普通任务数据均不泄露密码、passkey 或连接密钥。
- 登录和找回限流跨重启保留，并发、伪造转发头及过期清理不能绕过封禁。
- 清理预览及执行历史跨重启保留；逐条意图保存失败禁止删除；响应丢失/进程中断只核对，不自动重发删除文件操作。
- 使用隔离临时数据库和假外部服务完成后端、浏览器和真实 PM2 重启验证；保持原 222 项测试的业务断言。Docker 可用时验证卷权限，否则明确未实测。
